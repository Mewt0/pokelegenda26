# Логика предметов

Документ фиксирует, где сейчас лежит логика предметов, какие предметы реально есть в БД/магазине, и что уже работает в новом ядре.

## Где лежит логика

### Новое ядро

| Файл | За что отвечает |
|---|---|
| `src/Repository/InventoryRepository.php` | Инвентарь игрока, выдача/списание, экипировка предметов на покемона, заготовка применения предмета на покемона через `item_target_rules`. |
| `src/Controller/InventoryApiController.php` | API инвентаря: `/api/inventory/page`, `/api/inventory/battle`, `/api/inventory/equip`, `/api/inventory/unequip`, `/api/inventory/use-target`. |
| `src/Repository/ItemMarketRepository.php` | Каталог покемаркета, покупка товаров, покупка лотов игроков, кошелек, иконки через `public/img/items/index.json`. |
| `src/Controller/ItemMarketApiController.php` | API покемаркета: список товаров, покупка товара, кошелек. |
| `src/Game/BattleEngineService.php` | Использование боевых предметов и покеболов в PvE-бою. |
| `src/Repository/BattleRepository.php` | Проверка предметов в бою, списание предметов, дроп после боя, ордера Команды R для PvP. |
| `src/Repository/TrainingRepository.php` | Набор тренировки `330` и набор ослабления `678`. |
| `src/Repository/AdminRepository.php` | Админское создание/редактирование предметов и обновление индекса иконок. |
| `public/js/game-market-overlay.js` | Новый UI покемаркета на главной странице игры. |
| `views/game-start.php` | Инвентарь, боевой карман, target-use UI для предметов на покемона. |
| `public/img/items/index.json` | Карта `item_id -> файл картинки`. |

## Главные таблицы БД

| Таблица | Назначение |
|---|---|
| `items` | Справочник предметов: название, категория, флаги `uses`, `dress`, `battleuse`, старое поле `dopolnen`. |
| `items_users` | Предметы у игроков. |
| `market_shop_items` | Новый каталог покемаркета: цена, валюта, лимиты, сортировка, включен/выключен. |
| `item_target_rules` | Разрешение рендера меню “применить на покемона” и будущий ключ эффекта. |
| `pok_user` | Покемоны игрока, на них применяются конфеты/камни/TM/тренировки. |

## Что проверено по БД

Запросом к реальной БД проверены:

- структура `items`;
- структура `market_shop_items`;
- структура `item_target_rules`;
- все предметы `id <= 90`;
- все предметы, включенные в покемаркет;
- все предметы с target-use правилом.

## Важные выводы

1. Магазин сейчас умеет продавать предметы из `market_shop_items`.
2. Инвентарь умеет показывать предметы и открывать меню применения на покемона, если в `item_target_rules.enabled = 1`.
3. `effect_key=pending` означает: UI уже есть, но реального эффекта предмета еще нет. Новый API специально не списывает такой предмет, а возвращает ошибку `effect_not_implemented`.
4. Старые item_id осколков `24-38` и камней `40-44` нельзя переименовывать бездумно: на них завязан старый крафт камней.
5. Новые дубли камней `67/68/75/77` отключены в магазине, чтобы не ломать старую схему крафта и эволюций.
6. Для нормальной сортировки инвентаря лучше не полагаться на старое поле `items.category`, а добавить отдельный справочник категорий/правил: покеболы, TM, яйца, покемоны, квестовый дроп, расходники, эволюция, транспорт, валюта.

## Ближайшая логика, которую надо перенести

1. Конфеты: перенести эффекты `confetka`, `itemHarPoke`, `itemLevelPoke` в новый `InventoryRepository::useTargetedItem`.
2. Камни эволюции: перенести `evolutionItems` в новый сервис эволюций.
3. TM: сделать выдачу случайной атаки покемону с проверкой совместимости.
4. Витамины PP: дать выбор атаки покемона и увеличить PP/лимит.
5. Покеболы `90004/90005`: добавить коэффициенты ловли в `BattleEngineService`.
6. Ордер протекции `90003`: сделать отдельную механику защиты локации.
7. Крафт: перенести `kraft_1_obrab.php` в новую таблицу `craft_recipes` и API.
8. Сортировка инвентаря: добавить категорийные правила и фильтры UI.
