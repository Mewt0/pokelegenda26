# Перепись проекта под PHP 8.5.11

**Ветка:** `php85-migration` (создана 2026-10-07 от `codex/beta-foundation` @ `54925221`)
**Владелец плана:** DSH-агент · **Статус:** ветка создана, перепись не начата
**Источники:** карта проекта в `codebase-memory` (6203 узла / 24493 связи), живой код, статический скан устареваний, проверка доступности legacy-маршрутов по HTTP.

> **Границы и решения до начала работ** (уточнено 2026-10-07 после ревизии плана):
> 1. **`include/**` не правим** без отдельного решения владельца. По `AGENTS.md` это legacy «только чтение», поэтому правки P0-2 и любого устаревания в `include/**` начинаются только после явного разрешения. Пока это лишь зафиксированные находки.
> 2. **Открытый вопрос по базе ветки:** `origin/main` (`61905e86`, merge PR #6) **не содержит** двух локальных коммитов `codex/beta-foundation` (`3162b71f`, `54925221`). Ветка миграции сейчас стоит на `54925221` — то есть на том, что реально запущено. Прежде чем писать код, надо подтвердить базу: оставить `54925221` или переносить два коммита на `origin/main`.
> 3. **Успех не объявляется по тестам.** Отдельным критерием идёт проверка legacy-маршрутов, которые реально доступны по URL (см. §9), и отсутствие `Deprecated:` в логах.
> 4. **Старые результаты QA не считаются свежими** — базовая линия снята заново (§5, Ф1).

## 3. Что нужно переписать

### 3.1 Блокеры и устаревания в активном коде (P0)

| # | Файл:строка | Что не так | Почему важно | Правка |
|---|---|---|---|---|
| P0-1 | `include/function/Services_JSON.php:156` (и 509-510) | **Файл вообще не парсится на PHP 8**: `Array and string offset access syntax with curly braces is no longer supported` — синтаксис `$str{0}` удалён в **8.0**. Плюс неканонические касты `(integer)`/`(float)` на 509-510 (устарели в 8.5) | Это не «две запятые»: библиотека мертва целиком. Подключается только из legacy-боя: `include/files/fight_pve.world.php` (через `game.php:326,329`) → `battle.functions.tip.php:1372` и `battle.functions.php:1437`, причём `require_once` стоит **внутри функции `demagePokes()`** | Решение из двух: **вывести legacy-бой из эксплуатации** (современный бой живёт в `src/Service/BattleEngineService.php`) или портировать класс на `json_encode()`/`json_decode()`. Косметическая правка кастов смысла не имеет, пока файл не парсится |
| P0-2 | `include/function/chat.world.php:38` | `utf8_decode()` внутри `__u2c()` — устарел в 8.2. Функция конвертирует **UTF-8 → cp1251** для legacy-чата (рядом `__to_utf8()`, конвертирующий обратно) | ⚠️ Моя первая редакция предлагала `mb_convert_encoding($s,'UTF-8','ISO-8859-1')` — это **неверно**: `utf8_decode` не про кириллицу, и такая замена испортит текст. Здесь нужен `iconv('utf-8','windows-1251//TRANSLIT//IGNORE',$s)` (или `mb_convert_encoding($s,'Windows-1251','UTF-8')`) как замена именно fallback-ветки. Перед правкой — подтвердить кодировку данных в БД. Файл достижим только через `game.php:313` (**410**) и `include/files/live.ajax.php:48` — проверить второй путь отдельно |

**Проверка доступности (2026-10-07, авторизованный запрос):** все legacy-маршруты `game.php?go=*` отдают **HTTP 410 «Legacy route removed»** ещё до `require`-ов — см. `game.php:45-58`. Значит цепочка `game.php:325-330 → fight_pve.world.php → battle.functions*.php:1372,1437 → Services_JSON.php` **недостижима**.

**Отсюда важная поправка к моей же первой редакции плана:** я написал, что «обработка хода в legacy-бою фатально падает уже сейчас» — это была догадка по цепочке вызовов без проверки доступности, и она неверна. `Services_JSON.php` — **мёртвый код**, а не живой баг. Для миграции это понижает приоритет: файл можно не трогать до вывода legacy-экранов (P3), но нельзя оставлять его в списке блокеров переезда.

Смешивать нельзя: непонятно будет, что сломалось — версия или переписывание.

## 4. Окружение: как поставить 8.5.11

Ключевая деталь: **PHP работает как модуль Apache** (`E:\OSPanel\modules\php\PHP_8.1\php8apache2_4.dll`), а CLI сообщает `ZTS ... x64`. Значит нужна **Thread Safe (TS)** сборка для Windows, а не NTS.

1. Скачать Windows-сборку **PHP 8.5.11, VS17 x64 Thread Safe (Zip)** с windows.php.net (страница релиза: [php.watch/versions/8.5/releases/8.5.11](https://php.watch/versions/8.5/releases/8.5.11)).
2. Распаковать в `E:\OSPanel\modules\php\PHP_8.5\`.
3. Скопировать `php.ini-development` → `php.ini`, включить то же, что в 8.1, и обязательно:

   **Обязательные для игры:** `pdo_mysql`, `mbstring`, `curl`, `openssl`, `fileinfo`, `session`, `json` (встроено), `ctype`, `hash`, `iconv`, `zlib`.
   **Нужны инструментам:** `gd` (картинки/скриншоты), `mysqli` (не используется приложением, но включён в 8.1), `zip`, `sodium`.
   **Недоступны в стандартной сборке:** `imagick`, `enchant`, `odbc`, `pdo_pgsql`, `xsl` — проверить, что приложение их не требует (по composer.json требует только `pdo`, `pdo_mysql`, `mbstring`).
4. В OSPanel переключить версию PHP для домена `pokemonchic.com` на 8.5 и перезапустить сервер.
5. Проверить: `E:\OSPanel\modules\php\PHP_8.5\php.exe -m` содержит `pdo_mysql` и `mbstring`.

Если 8.5.11 для Windows ещё не собран под нужный компилятор — использовать ближайший доступный патч 8.5.x, отметив это в отчёте.

### Что это значит

1. **`/events.php` — живой баг на текущем PHP 8.1**, к 8.5 отношения не имеет. Варианты: отдать 410 со ссылкой на `/game/events` (как это сделано в `game.php:45-58`) или удалить файл. Решение — за владельцем, правка вне переписи.
2. **Legacy-бой и legacy-чат недостижимы** — это снимает нагрузку с P0-1 и понижает P0-2.
3. Пустые ответы (`/ban.php`, `/pInf.php`, `/itemsinpage.class3.php`) надо перепроверить после переезда: пустой ответ может быть и «ничего не делает», и «упал молча».
4. Проверку повторить после установки 8.5 — это и есть критерий «не объявлять успех по тестам».

### `php -l` по 449 файлам интерпретатором 8.5.11

**1 ошибка парсинга:** `include/function/Services_JSON.php` — тот самый мёртвый файл с `$str{0}` (синтаксис удалён в PHP 8.0). Больше ничего.

### ⚠️ Находка: два «падения» оказались настройкой `php.ini`, а не версией

Первый прогон дал 3 ошибки. Два файла — `admin/bb_news_admin.php` (`Unmatched '}'`) и `include/files/friends.game.php` (`Unclosed '{'`) — **на 8.1 парсятся, на 8.5 падали**. Причина не в версии:

| Параметр | PHP 8.1 (факт) | PHP 8.5.11 (было) |
|---|---|---|
| `short_open_tag` | **`1` (On)** | **`''` (Off)** |

В проекте **22 файла** используют короткий тег `<?` (не `<?php`). При `Off` эти участки становятся текстом HTML, и парсер видит несбалансированные скобки. Проверка гипотезы: те же файлы с `-d short_open_tag=1` → «No syntax errors». После приведения `php.ini` к 8.1 оба файла парсятся без флагов.

### Приведение `php.ini` к рабочему 8.1 (сделано, бэкап рядом)

Бэкап: `php.ini.bak-before-migration`.

| Параметр | Было в 8.5.11 | Стало | Почему обязательно |
|---|---|---|---|
| `short_open_tag` | `Off` | **`On`** | 22 файла с `<?`; без этого ломаются страницы |
| `date.timezone` | `Europe/Warsaw` | **`Europe/Moscow`** | Иначе сдвиг времени: турниры, боссы, кулдауны, дедлайны |
| `memory_limit` | `128M` | **`1536M`** | В 8.1 стоит 1536M; на 128M рискуем падением тяжёлых сцен (бой, integrity) |
| `upload_max_filesize` | `2M` | **`50M`** | Загрузка картинок (баг-репорты, аватары, скриншоты) |
| `post_max_size` | `8M` | **`50M`** | То же, иначе POST режется |

Остались как есть (совпадают или не критичны): `display_errors=On` (в 8.1 фактически тоже On), `default_charset=UTF-8`, `max_execution_time=0`, `opcache.enable=1` (в 8.1 было `off` — ускорение, но при переключении стоит проверить поведение с `filemtime`-версиями ассетов).

### Что это даёт

Фаза Ф2 фактически выполнена в части статики: интерпретатор 8.5 разбирает 448 из 449 файлов, единственный непроходящий — мёртвый код. **Домен ещё не переключён** — это следующий шаг (Ф3), и он требует только смены версии PHP у домена в OSPanel.
