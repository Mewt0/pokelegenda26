# План переноса игровых событий

Дата: 2026-05-25

## Текущее состояние

- Новый маршрут `/game/events` существует и показывает рабочую страницу активных/будущих событий, личных бустов и итоговых множителей.
- Legacy-вход `game.php?go=gameload` уже перенаправляется на `/game/events` и не должен оставаться источником исполнения.
- В новой админке уже есть раздел `Ивенты/бусты`, который работает с таблицей `game_event_boosts`.
- `RewardRepository::activeMultiplier()` уже умеет складывать глобальные и личные бусты из `game_event_boosts` и `player_boosts`.
- PvE уже применяет множители `exp`, `coins`, `drop`; в этом QA-блоке добавлена поддержка `catch` для ловли и `happiness` для прироста счастья после победы.

## Цель переноса

События должны управляться через новый стек проекта:

- route: `/game/events`;
- API: `/api/events/*`;
- админка: `/game/admin`, вкладка `Ивенты/бусты`;
- backend: сервисы, репозитории, JSON, CSRF, UTF-8;
- без исполнения legacy PHP из `include/files/gameload.world.php`.

## Новая архитектура

### Сервисы

- `GameEventService`
  - собрать активные события;
  - применить правила расписания;
  - отдать публичный список игроку;
  - объяснить, какие множители сейчас действуют.

- `GameEventRepository`
  - CRUD `game_event_boosts`;
  - чтение активных событий;
  - чтение личных бустов `player_boosts`;
  - фильтры по scope, времени, boost_key.

- `EventEffectResolver`
  - единая точка расчёта множителей;
  - поддержка `exp`, `coins`, `drop`, `quest_rewards`, `catch`, `happiness`;
  - правила суммирования: перемножение, кап `x20`.

### API

- `GET /api/events`
  - полный публичный payload раздела: активные события, будущие события, личные бусты, итоговые множители и QA-чеклист.

- `GET /api/events/active`
  - компактная карта активных эффектов для клиента без HTML и legacy PHP.

- `GET /api/events/effects/debug?context=pve&location_id=&pokemon_id=`
  - админская отладка: почему игрок получил такой множитель.

- `POST /api/admin/events`
  - создать или обновить событие.

- `DELETE /api/admin/events`
  - удалить с аудитом.

## Таблицы

### Уже используются

- `game_event_boosts`
  - глобальные события: опыт, монеты, дроп, ловля, квестовые награды, счастье.

- `player_boosts`
  - личные временные бусты от предметов.

### Рекомендуемые расширения

- `game_event_scopes`
  - связь события с локациями, покемонами, источниками (`pve`, `quest`, `market`, `npc`).

- `game_event_rewards`
  - гарантированные/редкие награды за участие в событии.

- `game_event_audit`
  - можно не заводить отдельно, если всё пишется в `admin_audit_log`.

## Механики, которые надо покрыть

- Опыт: множитель применяется к награде за PvE/PvP/квесты, если scope разрешён.
- Монеты: множитель применяется к монетам за бой и ивентовые награды.
- Счастье: прирост после боя усиливается бустом `happiness`.
- Дроп: шанс дропа умножается бустом `drop`, но не выше 100%.
- Ловля: шанс ловли усиливается бустом `catch`.
- Квестовые награды: `quest_rewards` умножает предметы и валюту из квестовых reward-методов.
- Личные предметы-бусты: `boost_exp`, `boost_drop`, `boost_money` должны создавать `player_boosts` и попадать в общий resolver.

## QA-матрица

| Сценарий | Действие | Ожидание |
|---|---|---|
| Нет события | Победа в PvE | Базовые опыт, монеты, счастье, обычный шанс дропа |
| x2 опыт | Создать `exp x2` | В логах и пуше опыта в 2 раза больше |
| x4 монеты | Создать `coins x4` | Монеты начисляются с множителем |
| x10 дроп | Создать `drop x10` | Дроп выпадает заметно чаще, шанс не выше 100% |
| x2 ловля | Создать `catch x2` | На одинаковом HP шанс ловли выше |
| x3 счастье | Создать `happiness x3` | После победы счастье +3 вместо +1 |
| Квестовый буст | Создать `quest_rewards x2` | Награда квеста удваивается |
| Истёкшее событие | `ends_at < now` | Событие не применяется |
| Будущее событие | `starts_at > now` | Событие видно как будущее, не применяется |
| Личный + глобальный буст | Предмет x2 + событие x3 | Итог x6, но не выше x20 |

## Browser QA

1. Включить тестовый ивент дропа через админку.
2. Провести 3 PvE боя и проверить появление предметов.
3. Включить `exp x2`, провести бой, сверить лог и DB `pok_user.exp`.
4. Включить `happiness x3`, провести бой, сверить `pok_user.happy`.
5. Включить `catch x2`, провести попытки ловли на низком HP.
6. Открыть `/game/events`: игрок должен видеть активные события, время окончания и эффекты.

## Backend QA

- Проверить `RewardRepository::activeMultiplier()` для каждого `boost_key`.
- Проверить истечение `game_event_boosts`.
- Проверить `player_boosts` с истекшим `expires_at`.
- Проверить, что неадмин не может менять события.
- Проверить, что POST без CSRF получает `419`.
- Проверить аудит создания, изменения и удаления события.

## Статус

- `drop`: работает и проверен через QA-дроп.
- `exp`: работает в PvE, нужен отдельный тест с событием x2.
- `coins`: работает в PvE, нужен отдельный тест с событием x2/x4.
- `quest_rewards`: поддерживается в `RewardRepository::grantItems()`, нужны end-to-end квесты.
- `catch`: добавлена поддержка множителя в ловле.
- `happiness`: добавлена поддержка прироста после PvE-победы и множителя события.
- `/game/events`: placeholder заменён на рабочий UI с активными событиями, будущими событиями, личными бустами и итоговой матрицей множителей.

## QA-прогон нового слоя

- `/api/events` должен возвращать JSON только авторизованному игроку.
- `/api/events/active` должен возвращать текущие множители без HTML и legacy PHP.
- `/game/events` должен открываться без `game.php?go=gameload` и без frameset.
- Если в админке включить `Опыт x2` со scope `PvE`, в `/game/events` и `/api/events` должен появиться множитель `pve.exp = 2`.
- Если включить `Шанс дропа x10`, в `/game/events` должен появиться `pve.drop = 10`, а PvE-награды должны использовать этот множитель.
- Если включить `Счастье x3`, PvE-победа должна увеличивать счастье с учётом множителя.
- Если включить `Шанс ловли x2`, ловля должна считать шанс с этим множителем.
- Истёкшие и выключенные события не должны попадать в активный список.
- Будущие события должны отображаться в блоке запланированных и не влиять на множители до времени старта.
