## 4. Пункты подробно

### 4.1. В базе нет ни одного внешнего ключа

Целостность держится только кодом. Результат виден в живых данных: 38 осиротевших
предметов, 63 покемона с несуществующим владельцем, 1 яйцо, 230 незавершённых строк
боёв. Любая правка инвентаря, разведения, комиссионки или наград может потерять или
задвоить объект игрока, и БД это не остановит — дефект `:pvp_user` уже ломал реапер,
а catch попадал в чужую PvP-строку через дубль `battles.id`.

Делать: FK на критичные связи (`items_users.user_id`, `pok_user.users`, `battles.user_1`,
`eggs.user_id`), а где легаси-данные FK не пускают — `CHECK`/уникальные ключи. Сначала
разбор 102 осиротевших записей (38+63+1) и проверка движка таблиц: на MySQL 5.5
MyISAM-таблицы FK не поддерживают вообще.

### 4.2. Классы-боги и метод на 261 строку

`attackLocked` — 260 строк в одном методе. Его нельзя ни протестировать по ветвям, ни
уследить глазами, и именно в нём жили «двойной клик начислил награду дважды» и «зависший
бой». Пока метод такой, следующая такая дыра появится снова.

Делать: распилить на чистые шаги — изоляция хода (мьютекс), расчёт урона, статусы,
награда, запись replay. `BattleEngineService` делится на 4–5 сервисов по 300–500 строк,
сам класс остаётся фасадом с прежним публичным API.

### 4.3. Слойность соблюдена наполовину

Правило «данные в `src/Repository`, логика в `src/Game`» работает в одну сторону: из
контроллеров SQL вычищен полностью, но в игровой логике осталось 69 прямых запросов
(`WildEncounterService` 27, `NpcDialogEventTrait` 22, `NpcDialogService` 16,
`StalePveBattleReaper` 4). Это те самые места, где рождались дефекты дублированных
PDO-параметров.

Делать: механический перенос 69 запросов в репозитории с сохранением SQL и семантики.

**Поправка к аудиту:** DI-контейнера в проекте нет. Зависимости собираются вручную
(`public/index.php:107-191`), и часть сервисов конструируют сами `tools/*.php`
(`fpe_quest_smoke:51-52`, `legacy_core_qa_smoke:42`, `location_npc_transport_smoke:48-49`,
`npc_runtime_audit_smoke:40`, `quests_minimum_smoke:37`). Перенос обязан обойтись
`src/Game/**` и `src/Repository/**`: конструкторы остаются совместимыми — репозиторий
собирается внутри сервиса из имеющегося `$db` либо принимается необязательным
параметром, иначе правка вылезает в `public/index.php:152,154` и в пять вызовов в
`tools/*.php`.

### 4.4. Нет глобального обработчика ошибок

`public/index.php:101` — единственное место про ошибки, и это только `display_errors` по
флагу `APP_DEBUG`. Фатальная ошибка в API отдаёт HTML со статусом 200, фронтенд делает
`response.json()`, получает мусор и падает молча. Отсюда «залипающие экраны» из
`TASK-020` и необходимость в каждом обработчике угадывать форму ответа.

Делать: один обработчик на входе — для `/api/*` всегда JSON с честным статусом, для
страниц понятная страница ошибки; плюс фронтенд-гард на content-type.

### 4.5. `SELECT *` — 56 раз

Это не про скорость. Это про то, что форма данных нигде не зафиксирована: репозиторий
отдаёт массив, вью и JS догадываются о полях. Поэтому переименование поля узнаётся на
бою, а `:pvp_user` задваивался при смене SQL — запрос нигде не типизирован.

Делать: в боевых и инвентарных путях явные списки колонок, на границе API —
типизированные объекты. Без этого пункты 4.1–4.3 возвращаются снова.

### 4.6. Легаси — 27 560 строк мёртвого веса

`include/**` — 240 файлов, 27 560 строк. Новый движок NPC читает ровно **один** файл —
`include/data.world.php` (`src/Repository/QuestRepository.php:781`; в
`AdminRepository.php:118` он же упомянут строкой описания в UI). Ссылок на
`include/rooms/**` в `src/**` одна и только в комментарии. Остальное не участвует в
runtime, но раздувает поиск, grep и диффы, а по `AGENTS.md:35` эти файлы нельзя трогать.

Делать: вынести `include/` в каталог-архив вне проекта, оставить рабочий
`data.world.php`. Ноль риска для runtime, ощутимое облегчение работы.

### 4.7. Фронтенд строит DOM строками

`public/js/game-start-runtime.js` — 2 541 строка ручной склейки HTML: `renderNpcDialog`
~302 строки, `renderInventoryTargetControls` ~220, `renderBattle` ~150. Отсюда найденный
DOM-XSS (`game-start-runtime.js:2222`), мерцание спрайта, перекрывающиеся тосты и
уезжающая нижняя панель: каждый раз лечится один симптом одного места.

Делать: в новых правках только `createElement`/`template`, а сам файл распустить по
экранам (бой, инвентарь, NPC, карта). Это зона DSH-агента, Codex и веб-каналы файл не
трогают.

## 5. Что в коде, наоборот, сделано хорошо (держать)

Чтобы картина не была однобокой — это правильные решения, и их не надо «улучшать»:

* игровые правила вынесены в каталоги (`BattleTransformationCatalog.php`,
  `BattleAbilityCatalog.php`, `BattleMoveEffectCatalog.php`), а не размазаны по `if`;
* 115 `catch (Throwable)` и ни одного `catch (Exception)` в `src/**` — ошибки не теряются;
* ноль `mysql_*`, ноль `@`-подавления, ноль `var_dump` в `src/**`;
* слой репозиториев реально работает, SQL из вью вычищен полностью (0);
* 33 уникальных ключа, `battle_id_sequence`, `GET_LOCK` на фоновых задачах — антидюп и
  параллелизм уже продуманы.
