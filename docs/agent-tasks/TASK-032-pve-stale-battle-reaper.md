# TASK-032 — P0: застрявшие PvE-локи блокируют комиссионную лавку

**Исполнитель:** Codex-агент · **Зона:** `src/**` (новый сервис/CLI реапера + `IntegrityRepository`), `tools/**` (смоук), `database/migrations/**` если понадобится · **Статус:** todo

## Проблема (измерено DSH-агентом 2026-10-09, не догадка)

В `battles` **211 незавершённых боёв** (`pobeda = 0`), и **~130 пользователей** висят с `users.pve = 1` и устаревшим `users.battleid`. Пример:

```
{"id":1,"login":"Tacos","pve":1,"pvp":0,"trade":0,"battleid":1791513193}
battles: {"id":1791513193,"user_1":1,"batl_tip":"pve","pobeda":0,"raund":1,"times":1791516793}
```

`CommissionMarketRepository::userBusy()` (`src/Repository/CommissionMarketRepository.php:1168`) считает такого игрока занятым, поэтому `createLot()` отвечает **«Сначала закончите бой или обмен»** (`:158`). То есть у ~130 аккаунтов **комиссионная лавка недоступна полностью**.

Бои при этом давно просрочены: у части записей `times` указывает на май 2026, у части — на 1970 год. Ничто их не закрывает.

## Почему это не ловит integrity

- `users.stale_active_battle` (`src/Repository/IntegrityRepository.php:118`) срабатывает **только когда строки боя уже нет** (`b.id IS NULL`). У Tacos строка есть → проверка молчит.
- `battle.active_unfinished` (`:132`) — это `warn` **без автофикса**, с комментарием «cleanup rules are reviewed in PvE/PvP phase». Именно поэтому в отчётах `ACCEPTED=4` и «всё чисто».

Побочный эффект: из-за Tacos красный гейт `quick` (`Commission hardening → expire.create`), смоук в изоляции даёт 36/36.

## Что сделать

1. **Реапер PvE-боёв** (новый сервис в `src/Game/`, по стилю существующих сервисов): закрывать бои `batl_tip='pve' AND pobeda=0`, у которых истёк срок. Срок брать из `battles.times`, а при `times <= 0` или явно битой величине — из явного TTL (задать константой и вынести в отчёт). Порядок для каждой записи: пометить бой завершённым/аннулированным → `UPDATE users SET pve=0, battleid=0 WHERE id=... AND battleid=<этот бой>`, всё в одной транзакции.
2. **Обязательный dry-run.** Первый прогон — только подсчёт и список затронутых id, без записи. Формат вывода — как у существующих смоуков проекта.
3. **Идемпотентность.** Повторный запуск на уже очищенном состоянии не должен менять ни одной строки (это проверяется в смоуке).
4. **Не закрывать живые бои.** Если `times` ещё не истёк — не трогать. Если по игроку есть открытый PvP-бой — не сбрасывать `pvp`.
5. **Смоук** в `tools/` (имя в стиле проекта): создаёт синтетический просроченный бой, прогоняет dry-run → реальный прогон → проверяет, что `userBusy` для этого игрока стал `false`, лот выставляется, повторный прогон ничего не меняет. Смоук должен убирать за собой.
6. **Integrity:** после реапера `battle.active_unfinished` должен оставаться диагностикой, но перестать быть «вечно горящим»: либо добавить проверку «просроченных боёв нет», либо сузить формулировку существующей. Решение и обоснование — в отчёте.
