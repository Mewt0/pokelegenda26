## Причина

Фатальная ошибка в API-обработчике сейчас отдаёт HTML и HTTP 200. Фронтенд вызывает `response.json()`, получает исключение парсинга и молча падает — экран остаётся в состоянии «идёт запрос» навсегда. Это корень задачи TASK-020 «залипающие экраны»; следствие видно не в одном месте, а во всех экранах сразу.

## Что замерено сейчас

* `public/index.php:101` — единственная настройка отображения ошибок:
  `ini_set('display_errors', $appConfig['debug'] ? '1' : '0');`
* Во всём `src/**` и `public/**` — **ноль** вхождений `set_error_handler`, `set_exception_handler`, `register_shutdown_function` (проверено сплошным grep'ом). То есть централизованного перехвата нет, `display_errors=0` лишь скрывает вывод, а не превращает сбой в корректный ответ.
* Единственная точка фактической отправки ответа — `Response::send()` (`src/Http/Response.php:21-29`). Всё остальное дерево отдаёт ответ через него.
* Несуществующий маршрут роутер отдаёт **HTML**: `new Response('<h1>404</h1>', 404)` (`src/Http/Router.php:34-36`). Для `/api/*` это тот же самый дефект: клиент ждёт JSON.
* Образец нужного поведения в проекте уже есть — ветка техработ `public/index.php:397-407`: для пути `/api/*` она отдаёт `{"ok":false,"error":"techwork","message":"…"}` со статусом 503 и `Content-Type: application/json; charset=UTF-8`, для страниц — `View::render('error', …)` со статусом 503. Бери этот код за образец формата, не изобретай новый.
* Фронтенд: **48** вызовов `response.json()` в **10** файлах `public/js/**` (сплошной grep). Единственное место с защитой от не-JSON — `public/js/admin-panel.js:933-962`: там заголовки собираются последними, не-2xx разбирается в `try/catch` и превращается в `{ ok:false, status, message }`. Остальные 47 вызовов защиты не имеют.
* Лог: `log_php_errors.txt` в корне проекта уже существует (17 434 658 байт на момент замера) и принадлежит Codex-агенту — писать в него нужно, чистить и переименовывать нельзя.

## Что сделать

1. Сделать **один** входной обработчик (`src/Http/**` или `src/Support/**`; выбери каталог, имя класса и обоснуй выбор в отчёте). Регистрируется в `public/index.php` до `$router->dispatch(...)` и снимает три класса сбоев:
   * `set_error_handler` — превращает предупреждения/`E_USER_ERROR` в исключение (`ErrorException`), чтобы они попадали в общий путь;
   * `set_exception_handler` — любой непойманный `Throwable`;
   * `register_shutdown_function` — фатальные, которые исключением не становятся: `E_ERROR`, `E_PARSE`, `E_CORE_ERROR`, `E_COMPILE_ERROR`.
2. Для пути `/api/*` (префикс `/api/`, определение уже есть в `public/index.php:392` — `$isGameApiPath`) обработчик **всегда** отдаёт JSON: честный HTTP-статус (500 для фатальной, 503 для недоступности БД, 500 для остального), тело `{"ok":false,"error":"<машинный код>","message":"<человеческий текст>"}`, заголовок `Content-Type: application/json; charset=UTF-8`. Ни HTML, ни пустого тела.
3. Для остальных путей — понятная страница ошибки со статусом 500 и **без стектрейса при `debug=false`**. Переиспользуй существующий `views/error.php` (принимает `$message`). Если его текст («Не получилось войти») для этого не годится — не создавай новый view сам, запроси его у DSH-агента в отчёте: `views/**` вне твоей зоны.
4. Логировать каждое перехваченное событие в `log_php_errors.txt` в формате, совместимом с текущим содержимым файла (посмотри первые строки перед правкой). При `debug=false` в лог уходит подробность, в ответ — нет.
5. Закрыть `/api/*` в роутере: ненайденный маршрут по пути `/api/*` должен вернуть JSON с `ok:false` и статусом 404, а не `<h1>404</h1>`. Где именно это сделать — в `Router::dispatch()` или в обработчике — реши и обоснуй; поведение HTML-страниц с 404 не менять.
6. Защита от двойной отправки: если заголовки уже отправлены (`headers_sent()`) или ответ уже ушёл, обработчик обязан только дописать лог, а не пытаться отправить второй ответ.
7. **Фронтенд-гард (отдельный патч для DSH-агента):** перед `response.json()` проверять `response.headers.get('content-type')` на `application/json`; при не-JSON возвращать `{ ok:false, status: response.status, message: 'Ошибка сервера' }` и не бросать исключение. Перечисли в отчёте файлы и строки, к которым относится этот патч, но не заявляй, что применил его.
