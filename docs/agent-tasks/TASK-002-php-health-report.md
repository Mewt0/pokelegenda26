# TASK-002 — PHP health report: lint + разбор лога ошибок

**Исполнитель:** Codex-агент · **Зона:** `tools/**` (новый инструмент) и `docs/reports/**` (отчёт) · **Статус:** todo

## Задача

Собрать объективную картину здоровья PHP-кода проекта и разобрать накопленный `log_php_errors.txt` (≈17 МБ). До сих пор никто не знает, сколько файлов не проходит `php -l` и какие ошибки встречаются чаще всего.

## Часть 1. Lint-сводка

Обойти все `*.php` в каталогах (рекурсивно):

- новый слой: `src/`, `public/`, `views/`, `app/`, `config/`, `tools/`
- legacy (отдельной группой): `include/`, `admin/`, корень проекта, `css/` (если есть php), `script/`

Для каждого файла выполнить `E:\OSPanel\modules\php\PHP_8.1\php.exe -l <файл>`.
Учесть: файлы с расширением `.php` внутри `downloaded_*`, `new_diz*`, `pok`, `tmp`, `storage`, `.codex_*`, `.git` — **пропускать**.

Результат: два списка (новый слой / legacy) с путями файлов, которые не прошли lint, и текстом ошибки.

## Часть 2. Разбор log_php_errors.txt

Формат строки: `[dd-Mmm-yyyy HH:MM:SS Europe/Moscow] PHP <Type>:  <message> in <path> on line <N>`.

Нужно:

1. Сгруппировать по `(тип ошибки, нормализованное сообщение, файл)` — нормализация: убрать конкретные значения, оставить шаблон.
2. Для каждой группы: количество, первое и последнее время.
3. Отдельно выделить: `Fatal error`, `Uncaught`, `Deprecated`, `Warning: Undefined`, `Trying to access array offset`.
4. Отдельно — по файлу-источнику: топ-20 файлов по числу записей, разбивка новый слой vs legacy.
5. Отдельно — уникальные типы сообщений с количеством (без файла), топ-30.

Инструмент оформить как `tools/php_error_log_report.php` с флагами `--json`, `--top=<N>`, `--root=<path>`, `--out=<file>`. Требования: PHP 8.1, `declare(strict_types=1)`, без зависимостей, файл лога только читается.

## Часть 3. Отчёт

Создать `docs/reports/php-health-2026-10-07.md`:

- сводка: сколько файлов проверено, сколько не прошло lint (новый слой / legacy);
- таблица «файл — ошибка lint» для нового слоя;
- таблица топ-20 групп ошибок из лога с количеством и периодом;
- таблица топ-20 файлов по числу записей;
- раздел «Кандидаты на исправление» — только новый слой (`src/`, `views/`, `public/`, `tools/`), с оценкой «1 строка / требуют разбора»;
- раздел «Legacy — не трогаем» с числами.

## Границы

Нельзя: править код (`src/**`, `views/**`, `public/**`), чистить или обрезать `log_php_errors.txt`, менять БД. Разрешено: создать `tools/php_error_log_report.php` и `docs/reports/php-health-2026-10-07.md`.

## Критерии приёмки

1. `php -l` на новый инструмент — чисто; запуск на проекте завершается за разумное время (< 5 минут).
2. `--json` отдаёт валидный JSON.
3. `docs/reports/php-health-2026-10-07.md` содержит все пять разделов из части 3 с реальными числами.
4. Числа в отчёте воспроизводимы: в отчёте указаны точные команды запуска.

## Доказательства

Команды, коды возврата, ключевые числа, путь к отчёту, топ-10 из каждой таблицы прямо в report-файле.
