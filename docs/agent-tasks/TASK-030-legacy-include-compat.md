# TASK-030 — Совместимость legacy `include/**` с PHP 8.5 (по решению владельца)

**Исполнитель:** Codex-агент · **Зона:** `include/function/chat.world.php`, `include/function/Services_JSON.php`, `include/files/live.ajax.php` (только чтение для проверки) · **Статус:** todo
**Основание:** владелец решил вынести правки legacy-зоны отдельной задачей. DSH-агент `include/**` не правит.

## Контекст

Проект переводится на PHP 8.5.11 отдельной программой работ (`PHP85_MIGRATION_PLAN.md`, ветка `php85-migration`). Архитектурная перепись legacy **в эту задачу не входит**. Здесь — только две совместимостные находки, каждая требует аккуратности.

## Задача 1 — `utf8_decode()` в функции `__u2c()`

**Файл:** `include/function/chat.world.php:38`

```php
function __u2c($s){ if ($s===''||$s===null) return $s; $r=@iconv('utf-8','cp1251//IGNORE',$s); if($r!==false&&$r!=='')return $r; $r=@utf8_decode($s); return ($r!==false)?$r:$s; }
```

`utf8_decode()` устарел в PHP 8.2 (удаляется в 9.0). Рядом функция `__to_utf8()` (строка 39) конвертирует обратно из `cp1251` в `utf-8` — то есть чат работает в **cp1251**.

**Обязательно до правки:** подтвердить фактическую кодировку данных, с которыми работает чат (таблица сообщений чата), и показать проверку в отчёте. Замена конвертера без знания кодировки испортит текст — это прямое требование владельца.

**Как правильно:** `utf8_decode` конвертирует UTF-8 → ISO-8859-1, для кириллицы это неверный fallback. Нужен конвертер именно в windows-1251:
`iconv('utf-8', 'windows-1251//TRANSLIT//IGNORE', $s)` либо `mb_convert_encoding($s, 'Windows-1251', 'UTF-8')`.
**Нельзя** заменять на `mb_convert_encoding($s, 'UTF-8', 'ISO-8859-1')` — такая замена была ошибочно предложена в первой редакции плана DSH.

## Задача 2 — `Services_JSON.php` (мёртвый код)

**Файл:** `include/function/Services_JSON.php` (806 строк)

Файл **не парсится на PHP 8**: `Array and string offset access syntax with curly braces is no longer supported` (строка 156) — синтаксис `$str{0}` удалён в PHP 8.0. Плюс неканонические касты `(integer)`/`(float)` на строках 509-510 (устарели в 8.5).

**Проверено DSH-агентом: путь мёртвый.** Цепочка `game.php:325-330` → `include/files/fight_pve.world.php` → `battle.functions.tip.php:1372` / `battle.functions.php:1437` недостижима: все legacy-маршруты `game.php?go=*` отдают **HTTP 410 «Legacy route removed»** (`game.php:45-58`) до `require`-ов. Класс используется только через `$oJson->encode($retJson)` в двух местах.

**Что сделать:**
1. Перепроверить недостижимость: `game.php?go=fight_pve` и `?go=fight_pvp` → 410; поиск других `require`/`include` этого файла и вызовов `new Services_JSON`.
2. Если путь действительно недостижим — **не портировать 806 строк**, а решить с владельцем: удалить файл вместе с двумя `require_once`, либо оставить как есть и зафиксировать как мёртвый код. В отчёте указать, что именно выбрано и почему.
3. Если найдётся живой вызов — заменить его на `json_encode()`/`json_decode()` (для массива скаляров поведение эквивалентно, оба экранируют не-ASCII в `\uXXXX`) и только потом трогать класс.
