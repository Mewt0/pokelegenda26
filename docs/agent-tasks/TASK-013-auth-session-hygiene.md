# TASK-013 — P1: гигиена авторизации и сессий

**Исполнитель:** Codex-агент · **Зона:** `src/Controller/AuthController.php`, `src/Security/Csrf.php`, `src/Security/Session.php` · **Статус:** todo

## Проблемы (подтверждены аудитом)

1. `src/Controller/AuthController.php:349` — ссылка сброса пароля строится из `HTTP_HOST`: `$scheme . '://' . $request->server['HTTP_HOST'] . $path`. Host header injection → письмо с токеном сброса ведёт на чужой домен.
2. `src/Controller/AuthController.php:78` — в сессию кладётся **хеш пароля** (`$this->session->put('password', ...)`), значение нигде не читается. Лишний секрет.
3. `src/Controller/AuthController.php:80,147` — `browse` пишется в сессию и **нигде не читается**: задуманная защита от переиспользования сессии не реализована. `:359` — секрет по умолчанию `'change-me-local-secret'`.
4. `src/Security/Csrf.php:15-26` — токен не ротируется, в том числе после `session_regenerate_id(true)` (`AuthController.php:75`), время жизни не ограничено.
5. `src/Security/Session.php:73` — `isHttps()` доверяет `HTTP_X_FORWARDED_PROTO` без проверки доверенного прокси (влияет на флаг `Secure` куки).
6. `public/index.php:204` — `GET /logout` без CSRF-проверки.

## Что сделать

1. Ссылку сброса строить из конфигурации приложения (жёстко заданный базовый URL; посмотреть, что уже есть в `config/app.php` / `$_ENV`), а не из `HTTP_HOST`. Если базовый URL не задан — использовать первый из белого списка доменов, а не заголовок.
2. Удалить запись хеша пароля в сессию.
3. Решить судьбу `browse`-отпечатка: **либо** реализовать проверку (сравнение при каждом запросе в middleware/guard с корректным секретом из `.env`, без дефолта — при отсутствии секрета проверку не включать и записать предупреждение), **либо** полностью удалить нерабочий код. Выбранный вариант обосновать в отчёте.
4. Ротировать CSRF-токен после успешного логина/смены пароля и ввести TTL (например 2 часа) с перевыпуском.
5. `Session::isHttps()` — учитывать `X-Forwarded-Proto` только при доверенном `REMOTE_ADDR` (согласовать со списком из TASK-011, если он уже сделан; иначе — не доверять вовсе).
6. `/logout` — сделать POST с CSRF; сохранить обратную совместимость: GET `/logout` может редиректить на страницу с кнопкой, но не разлогинивать. Если это ломает текущий UI — описать в отчёте и оставить GET, но тогда явно отметить риск.
