# TASK-048 — Явные колонки вместо `SELECT *` в боевых путях

**Исполнитель:** Codex-агент (`gpt-5.5`, `model_reasoning_effort=low`) · **Приоритет:** P1
**Зона (явно разрешена):** `src/Repository/BattleRepository.php`,
`src/Repository/BugReportRepository.php`, `tools/**` (для нового аудита)
**Запрещено:** менять формат ответов API, менять SQL-семантику, трогать `src/Game/**`
(в работе `TASK-047`/`TASK-052`)

---

## Причина

`SELECT *` — это не про скорость. Это про то, что форма данных нигде не зафиксирована:
репозиторий отдаёт массив, вью и JS догадываются о полях. Поэтому переименование поля
узнаётся на бою, а дубль именованного параметра (`:pvp_user`) проявляется при смене SQL —
запрос нигде не типизирован.

Всего в `src/**` **56** вхождений `SELECT *`. Задача закрывает **боевые пути** — те, где
ошибка в форме данных ломает бой.

## Что замерено сейчас

`SELECT *` в боевых путях:

| Файл | Строки |
|---|---|
| `src/Repository/BattleRepository.php` | 800, 2304, 2499, 2740, 2780 |
| `src/Repository/BugReportRepository.php` | 331 (`battles`), 341 (`battle_replays`) |

Остальные 49 вхождений (админка, рынок, разведение, квесты, профиль) в эту задачу **не
входят** — DSH-агент выдаст отдельную задачу по списку из отчёта.

## Что сделать

1. Добавить в `tools/` аудит `tools/select_star_audit.php` (зона `tools/**` — твоя):
   находит `SELECT *` по `src/**`, печатает файл:строка и итог, поддерживает `--self-test`
   на заранее известном числе. Число в выводе должно совпасть с 56 (или объясни
   расхождение в отчёте).
2. Для каждого из 7 боевых запросов заменить `*` на **явный список колонок**:
   * список бери из фактических обращений к результату — `grep` по имени метода и по
     ключам массива в `src/**` и `public/js/**`;
   * колонку, которую никто не читает, можно не выбирать — но каждую такую колонку
     перечисли в отчёте отдельно, с доказательством (команда grep и её пустой вывод);
   * если запрос уходит наружу через API, форма ответа обязана остаться прежней.
3. Проверить эквивалентность формы: до правки и после снять набор ключей, которые
   реально приходят на границе (боевое состояние, лог боя, replay). Способ — на твой
   выбор (например, временный скрипт в `tools/`, который дергает репозиторий напрямую);
   в отчёте — таблица «ключ: был/стал», добавленные и удалённые ключи.
4. Ни одного `SELECT *` в `BattleRepository.php` и в указанных строках
   `BugReportRepository.php` после правки быть не должно.

## Границы и запреты

* Менять только перечисленные файлы + новую утилиту в `tools/`.
* Не переименовывать ключи массива, не менять типы, не добавлять `JOIN` и не менять
  `ORDER BY`/`LIMIT`/`FOR UPDATE`.
* Не вводить DTO/классы на этом шаге: задача — зафиксировать форму запроса, типизация
  границы API будет отдельной задачей.
* Не коммитить и не откатывать чужие изменения.

## Приёмка

1. `php -l` по каждому изменённому файлу.
2. `php tools/select_star_audit.php --self-test` и прогон по `src/**` — дословный вывод.

4. `php tools/http_smoke.php --login=Tacos --password=REDACTED_USE_SMOKE_PASSWORD` и
