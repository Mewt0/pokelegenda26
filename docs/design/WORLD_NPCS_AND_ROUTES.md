## Связи локаций — требует переработки

DeepSeek дал связный граф, но **с обобщёнными названиями** («Луга Канто», «Стартовый город
Джотто»), которых в базе нет. Использовать как есть нельзя. Ценное в нём — принципы:

- водные пути требуют покемона с Surf;
- часть проходов только ночью, часть требует Cut;
- между регионами — паром;
- граф должен быть связным, без тупиков.

Его же замечания про односторонние связи (перепроверить на живых данных):

- Порт Джотто → Порт Церулина (25 → 23): паром только в одну сторону, нужен обратный рейс;
- Скалы (13) → Пещера (8): обратный проход, иначе тупик;
- Пещера (8) → Скалы (13): выход наверх, иначе «застрянешь до утра».

**Что сделать, чтобы это стало игрой:**

1. Привязать каждого NPC к конкретному id локации из таблицы выше и решить, каким механизмом
   он выдаётся (легаси `include/rooms/npc/*.php` или новая ветка в `NpcDialogService`).
2. Написать диалоги в `NpcDialogService` по образцу существующих (реплика + действие).
3. Для «обмена предметов» и «ремонта снаряжения» проверить, есть ли механика; если нет —
   сначала расчёт экономики, потом код (иначе получится кнопка, которая ничего не делает).
4. Граф переходов сверить с живыми данными: у проекта уже есть `MapMoveService`, который строит
   переходы. Сначала выяснить, какие связи реально работают, и только потом что-то менять.
5. Отдельно решить, нужен ли NPC «Странник Кай» как наводчик на квесты — у нас уже есть
   квестовый журнал, дублирование может запутать игрока.
