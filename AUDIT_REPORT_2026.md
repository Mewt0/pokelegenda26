# Отчет по бэкенд и game-logic аудиту Pokemon 8.0

## 1. Summary
Проведен глубокий аудит бэкенда, API и базы данных. Общий уровень готовности проекта оценивается в 70% для dev-сборки и 42% для открытой беты. Основная архитектура (MVC, Repository, Service) реализована верно, безопасность на уровне API (Auth, CSRF) обеспечена. Критические риски связаны с наследием старой БД (отсутствие AUTO_INCREMENT, записи с id=0) и потенциальными состояниями гонки при ручной генерации ID.

## 2. Critical bugs
| Priority | Module | Bug | Reproduce | Expected | Actual | Suggested fix |
|---|---|---|---|---|---|---|
| High | DB | Записи с id=0 в `items_users` | Проверить SQL дамп от 2026-05-09. | Все записи должны иметь уникальный положительный ID. | Есть 3 записи с id=0. | Применить миграцию `2026_05_10_000002_fix_zero_ids.sql`. |
| Medium | DB/Logic | Состояние гонки в `items_users` | Одновременное получение награды двумя игроками (редко) или два действия одного игрока. | Атомарная вставка с уникальным ID. | `InventoryRepository::addItem` использует MAX(id)+1 без блокировки. | Добавить `GET_LOCK` или перейти на `AUTO_INCREMENT` (начато в миграции 000006). |
| Low | Logic | Зависимость от системного времени | Поиск диких покемонов использует `CURTIME()`. | Зависимость от времени сервера может быть проблемой при тестировании или разных часовых поясах. | Используется SQL функция времени напрямую. | Передавать время из PHP как параметр. |
